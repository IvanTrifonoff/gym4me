# Versioning policy

## Канонический источник

Файл `/VERSION` содержит текущую версию релизной линии. Он обязателен для backend, frontend и документации.

## Правила

Версия увеличивается в каждом commit, который меняет приложение или публичную документацию релизной линии:

- `0.x.y` используется до первого стабильного релиза;
- `MINOR` — новый domain/API/UI capability без поломки старого контракта;
- `PATCH` — bugfix, security hardening, тесты и внутренние рефакторинги;
- `MAJOR` — удаление/изменение публичного API, миграция auth, несовместимая схема данных.

Каждый commit обязан иметь соответствующий раздел в `CHANGELOG.md`. Для серии коммитов одной задачи версии всё равно повышаются последовательно: это позволяет точно сопоставить deploy, diff и changelog.

## Формат записи

Каждая запись должна содержать:

- цель и пользовательский эффект;
- области Gym/Trainer/Athlete;
- API и data contracts;
- auth/passkey/security impact;
- migration/rollback notes;
- тесты и ограничения.

## Релиз

Релизный tag создаётся только после проверки `VERSION`, changelog, build, tests и чистого рабочего дерева. Production deploy не является частью обычного commit/push цикла.
